# Formula Provenance

Every non-trivial formula in this codebase is traceable to a specific paper and equation number. All 10 papers under `../research-papers/` (relative to the repo root, one level up from `capstone_project/`) were read in full before any formula was implemented — nothing here is taken on faith from a secondary source or an LLM-generated citation.

This matters because the project's **first** implementation pass was seeded from a one-shot LLM prompt that turned out to contain two fabricated citations (see "Corrected/rejected citations" below). Every entry in this document was independently verified against the actual PDF text.

### Not paper-derived: Stage 8's physics/weather profiles

`src/simulation/carla_config.py`'s per-mode (Normal/Degraded/Takeover) `PhysicsProfile` (target speed, tire friction, engine damping/max RPM) and `WeatherProfile` (cloudiness/precipitation/fog density/wetness, CARLA-only) values are **this project's own engineering choice**, not transcribed from any of the 10 uploaded papers — none of them specifies CARLA simulation parameters for this project's own system (see "Corrected/rejected citations" below for the fuller context on CARLA's absence from the proposal itself). They exist to give the RSS/sideslip formulas (#4, #8, reused verbatim, not reinvented) plausible per-tick inputs to react to. This is the same category of honest labeling as `multi_stream_fusion.py`'s softmax fusion weighting (#11) — a documented instantiation the project supplies, clearly distinguished from the cited, verified formulas around it.

## Corrected / rejected citations

The one-shot LLM scaffold that seeded this project's first implementation pass claimed two citations that, on direct verification against all 10 uploaded papers (and their combined ~150 references), do not exist:

- **"6-Layer ODD Environment Model (Sun et al., IEEE ITS Magazine 2022)"** — no such content exists in any Sun et al. paper in this project's paper set. The real Sun et al. paper present here (2024, IEEE TIV, cited as #2 above) is about robust-learning perturbation theory, not a layer model. The "6-Layer Model" concept genuinely exists in the ODD literature, but is correctly attributed by Hillen et al. 2025 to **Scholtes et al., "A 6-Layer Model for a Structured Description and Categorization of Urban Traffic and Environment," IEEE Access 2021**, building on **Thorn, Kimmel, Chaka, NHTSA DOT HS 812 623, 2018** — neither of which is among this project's uploaded papers, so neither is cited here as a formula source.
- **"Risk = Severity × Exposure × Likelihood (Lee et al., IEEE IV 2020)"** — no paper by this name/venue/year could be found in any of the 10 papers' bodies or references. This formula is not used anywhere in this codebase. Where a comparable rare-event risk estimate was needed (Stage 5), `src/odd/risk_estimation.py` instead implements Jiang et al. 2024's real, verified Kriging-based Subset Simulation framework (#9 above).
- **A dedicated "Module 6: CARLA Vehicle Physics Adaptation," with a concrete `carla.Client`/physics-profile/simulation-loop spec** — this exists only in `Capstone_OneShot_Prompt.txt`, not in the actual proposal document (`research-papers/CPG274_Proposal_updated.docx`). Direct inspection of the proposal found CARLA named exactly 3 times, all inside literature-survey summaries of *other* papers' (Jiang et al., Hasanujjaman et al., Salvi et al.) validation methodology — never as part of this project's own planned architecture, which commits only to generic "simulation based evaluation." Stage 8 (`src/simulation/`) was built later specifically to close this real gap: a genuine CARLA integration exists, but grounded in this project's own already-verified `rss_safety.py`/`sae_taxonomy.py` formulas (#4, #8 above) rather than the one-shot prompt's unverified physics constants. See the top-level README's "Known scope limitations" and `docs/FUTURE_STEPS.md`.

## Adapted, not literal — two explicitly documented deviations

1. **`risk_estimation.py`**: Jiang et al.'s Kriging-based Subset Simulation uses a Kriging surrogate model and Metropolis-Hastings resampling to generate new candidate points from a **live driving simulator**. This project has no simulator (see the no-CARLA/no-closed-loop-simulation scope decision in the top-level README). `estimate_failure_probability()` instead applies the same nested-threshold *decomposition structure* (Eqs. 17-19: a rare-event probability factored into a product of more-common conditional probabilities) directly to a **static population** of risk scores, with each level's threshold set as an empirical quantile of the surviving population rather than a Kriging-predicted one.
2. **`perception_monitor.py`**: Jiang et al.'s Algorithm 1 flags instability after more than 5 consecutive checks on **live video frames**. IDD-Lite is a static-image dataset with no true frame sequence. This module instead draws repeated perturbed versions of the same frame (reusing `perturbation_engine.py`) as a pseudo-sequence, and tracks SegNet-mask IoU / YOLO-confidence consistency across that sequence — the same consecutive-check-hysteresis pattern, applied to a different (documented, deliberately chosen) notion of "consecutive frame."

See each module's own docstring for the full detail of its adaptation.
